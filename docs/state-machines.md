# State transitions and ownership

This reference describes the application's stateful workflows, their owners, and the rules that
must survive future changes. The highest-risk transitions cross IndexedDB, file storage, tabs, or
remote GitHub requests. UI transitions must preserve those rules even when their work finishes late.

## Storage and data integrity

| Priority | Machine and owner                                                                   | States and transitions                                                                                                                                                            | Invariant and failure recovery                                                                                                                                                                                                                                                                   |
| -------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P0       | Vault coordination — `src/lib/storage/coordination.ts`, `database-lock.ts`          | Open → closing on `close()`; accepted work drains, then closed. Mutations queue behind the vault's exclusive lock.                                                                | Closed coordinators reject work. Web Locks coordinate tabs; an IndexedDB transaction provides the fallback and is released when its owner dies. Explicit operation contexts permit nested vault work without reacquiring the lock.                                                               |
| P0       | File replacement — `src/lib/storage/filesystem.ts`, `vault.ts`, `database.ts`       | Stable → durable previous generation → replacement journal → new files → committed metadata → cleanup.                                                                            | Metadata records the committed generation. Opening storage rolls back an uncommitted replacement or keeps a committed replacement. Cleanup failure must never undo committed metadata. File contents are materialized before deleting the previous trees.                                        |
| P0       | Note lifecycle — `src/lib/storage/vault.ts`                                         | Active → trashed on delete; trashed → active on restore; trashed → absent on purge or expiry.                                                                                     | Purge checks both current trash membership and the observed deletion timestamp. A stale trash listing cannot delete a restored or newly trashed note. Trashed notes cannot accept edits or new attachments.                                                                                      |
| P0       | Folder and link mutations — `src/lib/storage/vault.ts`, `src/lib/markdown-utils.ts` | Stable tree → validated proposed tree → journaled file replacement → atomic metadata, index, and backup-queue commit.                                                             | Moves and attachment ownership changes update paths and links together. Failures restore the previous tree. Path collisions are checked under the lock, including implied parent folders. Code, math, front matter, and HTML literals are excluded from link rewriting.                          |
| P1       | Note persistence — `src/lib/storage/vault.ts`                                       | Pending → file written → IndexedDB committed; quota failure → committed in IndexedDB with a pending file repair.                                                                  | IndexedDB text is authoritative. Opening a vault repairs note files before copying to a native mirror. File rollback occurs only when the authoritative metadata commit fails. Pending repairs are surfaced in storage status.                                                                   |
| P1       | Native mirror — `src/lib/storage/filesystem.ts`, `vault.ts`                         | Unconfigured / permission required / granted / error. Connect copies current files, persists the handle, then attaches. Disconnect removes the persisted handle before detaching. | OPFS is authoritative; mirror failures detach the mirror without retrying a metadata commit. Each locked operation reconciles the persisted handle and permission, so another tab cannot keep writing to an old disconnected folder. A replacement destination is synchronized before attaching. |
| P1       | Vault registry — `src/lib/storage/registry.ts`                                      | Legacy localStorage → migrated IndexedDB registry; registry additions and renames → transactional update.                                                                         | The active ID and descriptor list persist together. Concurrent additions merge; a rename changes only its intended descriptor. Browser settings failure cannot orphan a newly created vault. Visibility resume reloads the registry.                                                             |
| P1       | IndexedDB connection — `src/lib/storage/database.ts`                                | Opening → open; blocked → rejected; version change / close → closed.                                                                                                              | A late successful open after abandonment closes its connection. Transactions reject after closure. Storage shutdown drains work before closing the database.                                                                                                                                     |

`src/lib/storage/{filesystem,vault,database,coordination,registry}.test.ts` cover storage failure
paths and invariants. `test/e2e/storage.e2e.ts` exercises real browser persistence, concurrent edits,
resume, conflict recovery, and operation without Web Locks or localStorage.

## Backup, restore, and authentication

| Priority | Machine and owner                                                                                      | States and transitions                                                                                                                                             | Invariant and failure recovery                                                                                                                                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P1       | Backup queue — `src/lib/storage/database.ts`, `vault.ts`                                               | Local mutation → sequenced pending operation → captured operation → acknowledged operation.                                                                        | The sequence is allocated in the same transaction as the mutation. Note, attachment, folder, and pin metadata changes enqueue work. Acknowledgement removes only captured operation IDs, preserving later edits.                                                                                                         |
| P1       | GitHub backup — `src/lib/github.ts`, `storage/vault.ts`                                                | Idle → snapshot captured → blobs/tree/commit created → pending commit recorded → branch advanced → baseline and queue acknowledged. Failure leaves retryable work. | A separate per-vault backup lock spans network work without blocking local saves. A consistent full snapshot initializes a new target, even when another target already acknowledged its queue. A retry recognizes its own pending commit. Completion verifies the target and preserves the current auto-backup setting. |
| P1       | Backup scheduler — `src/routes/page-controller.svelte.ts`                                              | Ineligible / idle / scheduled / backing up / paused after conflict.                                                                                                | Eligibility is checked both when scheduling and firing: online, connected, ready vault, settled draft, no workspace mutation or confirmation. Runs capture their vault and request identity. Vault switches reset scheduling and conflict pause state.                                                                   |
| P1       | Restore selection — `src/routes/page-controller.svelte.ts`, `src/lib/components/restore-dialog.svelte` | Closed → selecting source → loading commits → ready selection → confirming → restoring → completed / failed.                                                       | Changing source invalidates commits and confirmation. Source and selected commit are fixed during restore. Confirmation binds the source, commit, and vault version. An offline event cannot dismiss an active replacement.                                                                                              |
| P1       | Restore application — `src/lib/github.ts`, `storage/vault.ts`                                          | Capture version → download snapshot → validate manifest and files → compare version under lock → replace atomically.                                               | A local edit during download rejects replacement. Content, folders, backup baseline, index, and queue commit together. A valid empty manifest restores an empty vault; no manifest and no note files is rejected.                                                                                                        |
| P1       | Authentication — `src/lib/github.ts`, `src/routes/page-controller.svelte.ts`                           | Disconnected → restoring / redirecting → connected; refresh → connected or disconnected; sign-out immediately invalidates local credentials.                       | A generation invalidates late session and refresh results. Failed restoration clears prior credentials. The controller subscribes to authentication changes instead of keeping an independent connected state after expiry.                                                                                              |
| P1       | GitHub requests — `src/lib/github.ts`                                                                  | Requesting → reading response → success / retry delay / refresh / failure / cancelled.                                                                             | The timeout covers body decoding as well as headers. Retry waits observe cancellation. Non-idempotent requests are not blindly retried. Requests check authentication generation before publishing results.                                                                                                              |

`src/lib/github.test.ts` and `test/e2e/github.e2e.ts` cover queue preservation, snapshot baselines,
head conflicts, restore preconditions, empty restores, expired sessions, and stalled responses.

## Workspace and asynchronous resources

| Priority | Machine and owner                                                                                           | States and transitions                                                                                                        | Invariant and failure recovery                                                                                                                                                                                                                                                                                                                   |
| -------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P1       | Workspace operations — `src/routes/page-controller.svelte.ts`                                               | Idle → navigation or mutation → idle. Vault: closed → opening → ready / failed → closing.                                     | One workspace operation runs at a time. The latest navigation request waits; conflicting mutations do not silently run in parallel. Naming and destructive callers receive failures. Remote reconciliation waits for the operation. Request identities reject obsolete opens and note loads.                                                     |
| P1       | Draft saving — `src/routes/page-controller.svelte.ts`                                                       | Loading / saved / unsaved / saving / error; errors distinguish storage failure and revision conflict.                         | An edit during an in-flight save requests another save. `settleDraft()` waits until the latest draft is durable before destructive work or navigation. A conflict preserves the draft and offers **Save a copy** with a new path; retry never silently overwrites the newer note. Housekeeping errors cannot relabel a committed save as failed. |
| P1       | Remote reconciliation — `src/routes/page-controller.svelte.ts`                                              | Idle → queued notification or visibility check → synchronizing → idle.                                                        | Compare durable vault versions on resume, and note revisions before applying text. Dirty text is retained on a real note conflict; unrelated metadata changes do not discard it. Reconciliation captures the vault and respects active workspace work.                                                                                           |
| P1       | Destructive confirmation — `src/routes/confirmation.svelte.ts`, `src/lib/components/settings-dialog.svelte` | Preparing → displayed → confirmed / cancelled / replaced / disposed. Clear: checking → version-bound confirmation → clearing. | Every superseded confirmation settles false. Preparation results are generation guarded. Clear verifies the confirmed version under the storage lock; a newer edit requires new confirmation. Busy destruction cannot be dismissed as though it had completed.                                                                                   |
| P1       | Import and export — `src/lib/markdown-transfer.ts`, `src/routes/page-controller.svelte.ts`                  | Idle → choosing / capturing → reading or writing → complete / cancelled / failed.                                             | Export uses one snapshot of metadata and materialized file bytes. | P1       | Attachments and image URLs — `src/routes/page-controller.svelte.ts`                                         | Reading → stored → adopted by the originating draft, or stale / failed → released. Preview: closed → loading → open → closed. | Ingestion captures the source note, path, and draft version before reading. Late completion cannot insert into a different note. Temporary URLs have an explicit adoption point and are released on stale or failed work. Partial attachment success refreshes the tree for recovery.                                                            |
| P2       | Lazy modules, styles, fonts — `src/lib/lazy-resource.ts`, resource loaders, `mermaid-preview.ts`            | Idle → loading → ready / failed; failed → loading on retry.                                                                   | Concurrent callers share one in-flight promise. A rejected promise is not cached forever. Font revisions prevent slower earlier selections from replacing current choices.                                                                                                                                                                       |
| P2       | Render worker — `src/lib/markdown-render-worker.ts`, `src/routes/preview-renderer.svelte.ts`                | Available → active with at most one queued latest render → available; timeout / worker error → failed; disposal → disposed.   | Superseded queued renders settle. Fatal failure rejects work, terminates the worker, and allows fallback. A 15-second deadline catches a silent worker. Disposed or obsolete workers cannot publish results.                                                                                                                                     |
| P2       | Search — `src/routes/page-controller.svelte.ts`                                                             | Idle → debouncing / pending → ready / failed. Query change invalidates prior work.                                            | Results must match query, request sequence, and vault. Failure clears busy state and allows retry; stale failures cannot erase newer results. Palette keyboard navigation skips disabled entries and returns no selection when all entries are disabled.                                                                                         |
| P2       | Find and history — `src/routes/find-replace.svelte.ts`, `src/lib/editor-history.ts`                         | Find closed / open / disposed; history recording / undo / redo.                                                               | Editor readiness retries are bounded. Disposal invalidates scheduled navigation. Undo and redo clear pending typing snapshots; loading another note resets document history.                                                                                                                                                                     |

Browser coverage lives in `test/e2e/{files,find,palette,panes,sidebar,settings,transfer}.e2e.ts`;
focused unit coverage lives beside the relevant helpers. Browser tests support `ONYX_E2E_PORT` and
require a strict port so another workspace cannot accidentally satisfy their server readiness check.

## Maintaining these machines

1. Keep one owner for each transition. Add commands to the existing coordinator rather than
   introducing another independent busy flag or queue in a component.
2. When adding an await, decide which identity it belongs to: vault, note revision, draft version,
   authentication generation, query, dialog request, or pointer. Recheck that identity before
   applying the result and release resources if the result is obsolete.
3. Put durable preconditions inside the storage lock. UI disabling and confirmation are useful
   feedback, but do not protect against another tab or a delayed request.
4. Keep file and metadata changes on the replacement protocol. Never retry a database commit
   because a best-effort mirror write failed.
5. Add regression coverage at the boundary that failed: interrupted journal recovery, delayed
   requests, simultaneous tabs, quota failures, or actual browser input. Keep pure scanner and
   selection behavior in focused unit tests.
6. When extracting more of the page controller, move a whole transition owner with its commands
   and cleanup. Its remaining presentation booleans need not become a dependency on a state-machine
   framework; discriminated states, request identities, and ownership rules are sufficient here.
